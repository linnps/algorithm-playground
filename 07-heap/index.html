Planned interactive demo

Watch insertions trigger sift-up and extractions trigger sift-down, with the array view and the tree view kept in sync side-by-side. Then a heapsort-vs-quicksort race using the same starting data — showing heapsort's predictable n log n vs quick's faster average but variable wall-time.

What it teaches

  • How a binary heap is just an array with three index arithmetic rules: parent (i-1)/2, left 2i+1, right 2i+2.
  • Why building a heap is O(n), not O(n log n) — bottom-up sift-down dominates.
  • When you'd actually pick heap sort over quick sort: when worst-case latency matters more than average throughput.
